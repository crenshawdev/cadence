# Phase 4: Derivation and the internal spine - Plan 2

## Goal

Use one lifecycle vocabulary at compatibility intake, refuse contradictory declarations, and specify the adoption transition that retires an imported assertion while retaining its provenance and exact resume data. Exercise those production functions with cold/warm snapshot fixtures and real-store restart tests before PLAN-3 connects memo key calculation and the binary query adapter (D-04, D-05, D-06; AC5, AC6).

## Must be true when done

- AC5: Phase 3/current unplanned accepts canonical unplanned and both legacy unplanned aliases through production normalization/comparison. Invalid statuses and incompatible live assertions refuse; closed/all-complete/paused cases follow the normalized rules. Store round trips preserve original fields, exact Next and hold, and an adopted assertion no longer blocks a later legitimate advance (D-05).
- AC6: Production consistency querying refuses each applicable ROADMAP/cursor contradiction with `state-conflict`, source and both compared values, against both absent and populated memo fixtures. Each failure returns no candidate and leaves source/store bytes unchanged; correcting the assertion permits a candidate (D-04, D-05).
- Compatibility validation does not trust imported `available:true`, and a retirement marker is produced only in the same pure snapshot update as its accepted memo payload (D-05, D-06; `crates/cadence/src/import/decisions.rs:50-51` is where permissive `available:true` is granted over unvalidated status/next/updated).
- No legacy alias becomes a second native lifecycle enum, and no success-with-drift return can bypass the consistency step (D-04, D-05).

## Context

D-04 and D-05 bind normalization and refusal; D-01 binds the bounded answer, D-06 binds cursor location and adoption, and D-07 binds reobservation. AC/D ids refer to `.planning/phases/4/CONTEXT.md`; E ids refer to `.codex-analysis/phase-4-evidence-set.md`. PLAN-1's Tasks prescribe the shared capture/derivation/query interfaces; verify they have landed before using them. This plan must not duplicate the parser, truth table or I/O adapter (D-01, D-03).

Import retains `available`, phase/total/name/status/next/updated and `original_fields`, but accepts more than frozen cursor grammar validates (`crates/cadence/src/import/decisions.rs:26`). It writes this record at `data.cursor` alongside `import`, `source_evidence` and `archive` (`crates/cadence/src/import/mod.rs:338`). Native compatibility intake consumes that retained value, not a fresh STATE read (D-06). Frozen cursor grammar requires a named phase, status, Next and a date-shaped Updated (`cadence-core/bin/lib/planning-files.mjs:27`); frozen agreement omits canonical unplanned and reports drift within successful status (E12-E15). D-05 intentionally changes that agreement policy and the closed-cycle alias asymmetry; do not restore either.

The existing store can persist arbitrary snapshot `data` through `Operation::RewriteSnapshot` and reopen it with integrity validation (`crates/cadence/src/store/writer.rs:19`, `:165`, `:242`; `crates/cadence/src/store/model.rs:143` is `parse`, which calls `validate` at `:145`). Use that existing writer in integration fixtures, with an explicit fixture policy, to prove the pure adoption/consistency contracts. The fixture supplies an opaque accepted-memo payload; it does not implement key derivation, memo hit selection or a new storage engine. PLAN-3 supplies that production composition and reruns these contracts through it. This separation makes AC5/AC6 executable here without claiming AC3/AC4 (D-03-D-06).

## Tasks

### Task 1: Normalize legacy cursor intake into canonical status and hold

- **Files:** crates/cadence/src/derivation/mod.rs, crates/cadence/src/derivation/model.rs, crates/cadence/src/derivation/compatibility.rs, crates/cadence/src/derivation/tests.rs
- **Action:** Add `CompatibilityCursor::{Unavailable, Assertion, Held}` and `CursorProvenance` retaining the untouched input JSON plus phase, total, name, original status, exact Next, Updated and original fields. Implement pure `normalize_imported_cursor(&Value)` and an explicit pure `normalize_legacy_state(&[u8])` compatibility adapter, sharing the status mapping and grammar validation. The STATE adapter performs no I/O; native queries will use only the imported value (D-05, D-06). Validate field presence/types, the frozen phase/total/name grammar and date shape using original fields when present; compare parsed originals to corresponding structured fields so permissive import cannot make malformed input authoritative. Missing/unparseable cursor is unavailable and retains provenance; a structurally valid cursor with an unknown nonblank status returns `InvalidStatus { source, original_status }` with code `invalid-status`. Accept exactly the native four strings plus `ready to plan`/`context gathered` -> unplanned, `phase complete` -> complete, and `paused` -> held. Do not lowercase unknown text or trim/normalize the stored Next. Preserve the exact supplied imported Next and original record; preserve the STATE adapter's parsed Next separately from its untouched source bytes (D-05; E12-E15; `crates/cadence/src/import/decisions.rs:33`).
  **Blank-name and blank-Next rejection are NEW native constraints, not reproduction of the frozen reader.** Frozen `parseCursor` accepts a blank name - `(.+)` matches `"   "`, so `Phase: 3 of 4 (   )` parses (`cadence-core/bin/lib/planning-files.mjs:29`) - and its `Next:\s*(.+?)\s*$` lets `\s*` cross a newline, so an empty `Next:` line consumes the following `Updated:` line as its value (`:31`). Implement these two as explicit line-bounded nonblank field checks. An executor that merely ports the frozen grammar will build the permissive behavior and fail this task's own Verify.
- **Verify:** `cargo test -p cadence --lib derivation::tests::ac5_normalize` must exercise the actual imported-JSON and explicit STATE-byte paths, asserting canonical unplanned for all three spellings, planned/executed/complete aliases, a distinct held cursor for paused, and named invalid-status refusal for an unfamiliar nonblank word. Missing required lines, bad date shape, blank name/Next and inconsistent original/structured fields must remain unavailable even with `available:true`; original JSON/fields and the exact Next string must compare equal before and after normalization (AC5; D-05, D-06).

### Task 3: Define atomic intake retirement as a snapshot transformation

- **Files:** crates/cadence/src/derivation/mod.rs, crates/cadence/src/derivation/model.rs, crates/cadence/src/derivation/intake.rs, crates/cadence/src/derivation/tests.rs, crates/cadence/tests/derivation_consistency.rs
- **Action:** Define the D-06 namespace `data.derivation` with two siblings, `memo` (opaque to this plan) and `intake`. Define `IntakeRecord { version: 1, source: "data.cursor", original_cursor, normalized, retired: true }`, with normalized hold/phase/Next retained as provenance. Implement `select_intake(&Value)` and pure `adopt(data, accepted_memo, validated_intake)` as the sole retirement transformation. A missing retirement marker means the imported assertion is applicable; a valid retired record whose `original_cursor` equals the current raw `data.cursor` makes it historical. A changed raw cursor becomes unconsumed intake and is compared again, without pretending it changed the lifecycle key. Malformed retirement metadata refuses as a typed invalid-intake error; it cannot suppress comparison. `adopt` clones the complete existing object, preserves every unrelated key and raw `data.cursor`, and installs memo plus retirement together. Allow null data to become an object for a genuinely fresh store; refuse other nonobject data rather than discarding it. Updating a memo with already retired intake preserves its history; no standalone mark-accepted method exists (D-05, D-06). Build the AC5 integration harness around these production functions and the real `Store`/`Filesystem`, using `RewriteSnapshot` only in the fixture. Supply a clearly labelled opaque memo fixture, never a pretend production input hash. Seed and read the store in separate child invocations of this test executable, following the existing child-driver pattern (`crates/cadence/tests/store.rs:33`, `:71`).
- **Verify:** `cargo test -p cadence --test derivation_consistency ac5` must derive/normalize/check/adopt through the production functions, await the real writer, reopen in a fresh child process, and assert exact raw cursor, original fields, hold and Next preservation. Advance the artifacts and matching ROADMAP consistently, then require derivation to advance while the unchanged retired assertion is ignored. The same stale assertion without retirement must conflict; changing `data.cursor` after retirement must re-arm intake. Assert failed normalization/comparison calls never call adoption or the writer, and one persisted snapshot contains both the supplied memo fixture and retirement, never just retirement (AC5; D-05, D-06).
