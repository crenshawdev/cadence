# Phase 4: Derivation and the internal spine - Plan 3

## Goal

Persist the bounded lifecycle memo through the existing owner, always compare it with fresh derivation, and refuse same-input disagreement without repair. Connect the captured inputs and mandatory consistency checks to the resident binary service, preserving imported provenance and recording successful intake in the same acknowledged store update as the memo (D-03-D-07; AC3, AC4).

## Must be true when done

- AC3: Each consumed observation/version component changes the production key when independently mutated; all stated exclusions leave it stable, including a memo write itself. An encoder omitting SUMMARY presence or skip-reason bytes is rejected by the same table (D-03).
- AC4: A fresh process reloads the persisted memo, recomputes the full answer and accepts equality. Validly stored same-key answer corruption or malformed memo returns `derivation-conflict`, identifies differing fields, and leaves bytes unchanged; a consistent artifact edit yields a new key and succeeds (D-04).
- Native query publication composes the earlier plans' input-change and declaration guards; no warm memo skips fresh derivation or compatibility checks for unconsumed intake (D-04, D-05, D-07).
- One awaited writer operation installs memo and intake retirement together, preserving unrelated data and imported provenance. A failed store write is never a successful query (D-06).
- Store integrity checks remain separate from lifecycle keys, and no lock primitive enters `src/store/` (D-03, D-06; `crates/cadence/src/store/model.rs:124`, `crates/cadence/src/store/writer.rs:148`).

## Context

D-03 fixes the exact key boundary; D-04 fixes hit/miss/disagreement; D-06 fixes location and writer; D-07 fixes reobservation. D-01/D-02's answer and D-05's vocabulary/adoption must already satisfy PLAN-1/PLAN-2's verification before this plan runs. AC/D ids cite `.planning/phases/4/CONTEXT.md`, and E ids cite `.codex-analysis/phase-4-evidence-set.md`. References to earlier plans' new symbols below are required handoffs to inspect, not claims about the current checkout.

Two checked integration gaps require narrow leases. `Operation::Read` currently returns cached `View` before revalidation (`crates/cadence/src/store/writer.rs:192`); `revalidate` already compares observed store bytes/identities (`:300`), and snapshot parsing independently checks integrity (`crates/cadence/src/store/model.rs:130`). Also, `Session::request` wraps snapshot replacements under `data.current`, retaining only the import manifest at the top level (`crates/cadence/src/import/mod.rs:402`). Sending the new full-data memo through that wrapper would relocate cursor/provenance. Add explicit checked-read/conditional-replacement operations and a session method that preserves full data; do not silently rely on the old operations having those semantics (D-06).

Reuse the existing resident request owner and `SessionFactory` root/session ownership, not a second writer/index service (`crates/cadence/src/recall/mod.rs:196`, `:317`; `crates/cadence/src/import/mod.rs:473`). Writes must still pass policy validation, transaction commit, disk confirmation and their own reply (`crates/cadence/src/store/writer.rs:111`, `:247`, `:281`; `crates/cadence/src/store/transaction.rs:129`). No new public transport is needed (D-04). Only the leased files may change; fixtures live inline or in temporary directories.

- **Action:** Implement pure `encode_inputs` and `input_key` over PLAN-1's immutable `CapturedInputs`, using the existing `store::model::digest` SHA-256 helper (`crates/cadence/src/store/model.rs:99`). Define domain tag `cadence.lifecycle`, encoding version 1 and semantic parser/derivation version 1 as distinct constants. Encode unsigned counts/lengths in fixed big-endian u64, enum outcomes as explicit byte tags, and strings/byte arrays as length then bytes; numbers use the same canonical `PhaseId` representation/address rules as capture, never original ROADMAP number spelling. Encode in D-03 order: tag/versions; normalized absolute root address and existence outcome; ROADMAP read outcome/all successful bytes; ordered phase count, then for every declaration numeric id, addressed relative path, listing outcome, count and sorted admitted PLAN basenames, SUMMARY existence outcome, UAT read outcome/all bytes. Repeated entries encode their shared captured observation without rereading it. Encode failed outcomes with stable category codes only, not localized diagnostic strings. An encoder may inspect failed captures for AC3, but query validation must reject them (D-03, D-07). Hash raw ROADMAP/UAT bytes, not parsed summaries; exclude mtimes, inodes, nonmatching entries, bodies of PLAN/SUMMARY and every D-03 excluded file, snapshot field and runtime value. Add table rows for each field/tag/count/order/version boundary, including synthetic independently mutated captured entries where real capture would correlate fields. Keep those synthetic fixtures encoder-only, not admissible query captures.
- **Verify:** `cargo test -p cadence --lib derivation::tests::ac3` must independently mutate domain/encoding/semantic version, root address/probe, ROADMAP outcome/bytes, phase count/order/id/path, listing outcome/PLAN count/names, SUMMARY outcome, UAT outcome/bytes and failure category; every mutation must change the key. The shared table must reject test-only encoders that omit SUMMARY existence or omit UAT reason bytes (AC3). `cargo test -p cadence --lib derivation::tests::encoding_boundaries` must distinguish ambiguous concatenations and reordered semantic entries while yielding fixed expected bytes/hash for a version-1 fixture (D-03).

### Task 2: Compare typed memos with freshly derived answers

- **Files:** crates/cadence/src/derivation/model.rs, crates/cadence/src/derivation/query.rs, crates/cadence/src/derivation/intake.rs, crates/cadence/src/derivation/memo.rs, crates/cadence/src/derivation/tests.rs
- **Action:** Define `LifecycleMemo { encoding_version, semantics_version, input_hash, answer: Lifecycle }` stored at `data.derivation.memo`, and pure `check_memo(raw, key, fresh) -> MemoDisposition::{Hit, Miss}`. Absence is a miss; explicit null, malformed required fields/types/hash, invalid native status, impossible answer structure, or malformed namespace is `DerivationConflict`, never overwrite permission (D-04). A structurally valid different version or hash is a miss; validate a versioned envelope before taking that branch, and do not deserialize an obsolete answer as current semantics merely to compare it. Preserve unknown version payloads as opaque only when their envelope is well formed; corrupt current-format payloads remain conflicts even under a changed key. A same-version/same-key memo must compare every field: cycle/current/total, ordered phases, ids/names/plans/status, UAT option presence and every counter. Produce deterministic differing paths such as `phases[0].uat.skipped`; include the requested hash and available stored hash in `DerivationConflict`, stable code `derivation-conflict`. Invalid memo errors name the malformed field when available. Always use the freshly derived answer as the success candidate; never return the memo without comparison. Keep declaration checking ahead of memo hit/miss selection; extend PLAN-2's adoption transformation to accept the typed, validated memo only in the production path, retaining its pure fixture boundary for existing tests (D-04-D-06).
- **Verify:** `cargo test -p cadence --lib derivation::tests::memo_comparison` must mutate each answer field under one unchanged key and assert derivation-conflict with its exact differing field; include reordering plans/phases and absent versus zero UAT counters. Missing memo and valid changed-version/hash rows must return Miss, equality Hit, and malformed/null memo or unknown native status conflict. A test-only unconditional-hit variant must be rejected by the corrupt-answer assertions; valid old-version envelope and malformed current-version payload must follow distinct branches (AC4; D-04).
