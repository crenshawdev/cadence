# Phase 2: The golden harness - Plan 1 (the fixtures, the manifest and the recorder's spine)

## Goal

Plans 2 and 3 must not be dispatched until this plan has landed: plan 2
extends the recorder this plan writes, and plan 3 reads the recordings plan 2
commits. `execute.md:28` runs plan files in numeric order and
`.planning/config.json` has `parallelization.enabled: false` (measured
2026-09-05), which is what carries that dependency today; confirm it is still
false before dispatching this phase.

Parity against `v3.7.12` is a test that runs, not a claim. This plan builds
the front half of the JavaScript side of the instrument: fixture `.planning`
bundles derived from the frozen tag for every operation on the parity surface,
the invocation manifest that names all 74 operations, and a committed recorder
that runs the frozen scripts hermetically and writes deterministic recordings,
proven end to end on the slice's read operations. Plan 2 (sequential, after
this one) extends that recorder to the git-dependent and write-side
operations, pins every remaining source of nondeterminism, runs the full
manifest, and adds the drift check; plan 3 is the Rust side that reads the
recordings. Nothing in the binary is ported here, and nothing under
`cadence-core/` changes.

### Task 2: The recorder records the slice's read operations hermetically (tracer bullet)

- **Files:** crates/cadence/tests/golden/record.mjs, crates/cadence/tests/golden/operations.json, crates/cadence/tests/golden/recordings/
- **Action:** Write the recorder and the first manifest entries: `status`,
  `replay-check --phase 1`, `cursor get` and `plan-overlap --phase 1` on the
  slice bundle, plus one refusal, `plan-overlap --phase 9`, which the seam
  answers `no-phase-dir`. `operations.json` is a JSON array of INVOCATIONS,
  each an object with `invocation` (unique id, also the recording's file
  stem), `operation` (the arm id from the inventory in Tasks 3 and 4),
  `bundle`, `script` (repo-relative path under `cadence-core/bin/`), `argv`
  (array; the literal token `<FIXTURE>` stands for the scratch copy's absolute
  root and is substituted at run time), optional `stdin` (string), and `git`
  (boolean, plan 2 Task 1). The recorder takes a repeatable `--only <invocation>`
  flag that restricts a run to the named invocations - every later task's
  Verify leans on it - and refuses an invocation with `git: true` by name,
  exiting non-zero and writing no recording, until plan 2 Task 1 replaces that
  refusal with the repository setup. For each invocation the recorder: copies
  the bundle into a fresh `mkdtemp` directory under the OS temp root and
  resolves that path with `realpath` (macOS reports `/var/...` for
  `/private/var/...`, and a token substitution against the unresolved spelling
  misses); runs `process.execPath` on the script with cwd set to the scratch
  root; builds the child environment FROM SCRATCH rather than inheriting
  `process.env` - `PATH` pointing at ONE scratch `bin/` directory holding
  symlinks to the running `node` and to `git` and nothing else (so `gh`,
  `glab`, `npx`, `eslint` and every other tool are unreachable on every machine
  alike), `HOME` at an empty scratch directory (so `homedir()`-derived defaults
  in `lib/config-merge.mjs`, `worktree-base.mjs` and `review-provider.mjs`
  never reach the real home), `TZ=UTC`, `LC_ALL=C.UTF-8`, `LANG=C.UTF-8`, and
  the three overrides D-13 names - `CADENCE_GLOBAL_CONFIG` at a global-config
  file the bundle supplies (an empty JSON object unless the manifest names
  one), `CADENCE_MANAGED_SETTINGS` and `CADENCE_USER_SETTINGS` at an
  empty-object JSON file inside the scratch copy; captures stdout, stderr and
  the exit status; parses stdout as one JSON object when it is non-empty (the
  seam contract) and keeps `null` otherwise; replaces every occurrence of the
  scratch root with `<FIXTURE>` and of the repository root with `<REPO>` in the
  envelope, stderr and file contents; and writes `recordings/<invocation>.json`
  as `JSON.stringify(_, null, 2)` plus a trailing newline. The recording
  contract, BINDING ON PLANS 2 AND 3, is exactly these top-level keys in this
  order: `invocation`, `operation`, `bundle`, `script`, `argv`
  (post-substitution, tokens restored), `stdin`, `env` (the pinned variables as
  passed, tokens restored), `node` (the major component of the running
  interpreter's `process.versions.node` as a decimal string - the children run
  on `process.execPath`, so it is theirs too; Node's own stderr diagnostics
  vary by major, and plan 2 Task 4's drift check refuses a run under another
  major by this key instead of showing an unexplained byte diff), `exit`,
  `stdout` (parsed object or null), `stderr` (string), `files` (object,
  relative path to post-run text - `{}` until plan 2 Task 2), `deleted` (array
  - `[]` until plan 2 Task 2). The contract has one sibling file,
  `crates/cadence/tests/golden/normalization.json`, the clock-field rules both
  the recorder and the Rust test apply; plan 2 Task 3 fixes its shape and
  writes it, and this task does not create it. Keep the envelope's own key
  order as emitted (the seam fixes it, D-12); do not sort keys. Delete the
  scratch copy after each invocation. Never open `CADENCE_TEST_SEAM`.
- **Verify:** `node crates/cadence/tests/golden/record.mjs` then
  `cp -r crates/cadence/tests/golden/recordings "$SCRATCH/a"` then a second run

  prints nothing; the `status` recording's `stdout.ok` is `true` with a

  `crates/cadence/tests/golden/` (a directory lease); plan 2 extends
  `record.mjs`, `operations.json` and `recordings/` inside it, and plan 3
  leases `crates/cadence/tests/golden.rs`, `crates/cadence/src/envelope.rs`,
  `crates/cadence/Cargo.toml` and `Cargo.lock`. The phase needed more capacity
  than one plan's eight-task ceiling once the manifest and the bundles were
  split along their seams, and the contract's answer is more plans, sequential
  where they share declared files - never merging concerns back into one task.
  CONTEXT's `Plan shape` asked for multiple plans at the fixtures/recorder
  versus Rust-comparison seam, and that seam is honored; the ordering is the
  one deviation from a parallel reading of it, and it is stated in each Goal.
- **The manifest is two tasks and the bundles are two tasks by size.** The 43
  `planning.mjs` arms and the 31 entry-script arms are one concern by purpose
  and two by context cost - each half means reading a different set of
  handlers to find its refusal arms; the tag-derived bundles (a, b) are
  re-rooting, the synthesized bundles (c-f) are design. Verifiability was
  never the problem; a single executor pass was.
- **74 operations, not the roadmap's 72.** The roadmap's sizing ("43 planning
  subcommands and 29 reached through the entry scripts, plus 4 tooling
  selectors") does not record which arms fell into which bucket. This plan's
  rule is explicit - every leaf arm of every phase-16 entry script's dispatch -
  and yields 43 + 30, plus `worktree-base resolve` because D-09 and D-13 name
  it. Phase 18 retires `worktree-base.mjs` and `plan-overlap`, so their
  recordings are reference material that never activates; the pending count
  plan 3 prints will carry them until phase 18 decides how to mark retired
  operations.
- **D-09's bound and D-14's two rules are superseded** by the Scope boundary
  revised 2026-09-05 (whole parity surface; every source of nondeterminism).
  Plan 2 Task 3 keeps D-14's spirit by naming each clock field individually
  rather than scrubbing dates, which is what D-12 warns against.
- **REQUIREMENTS.md is synthesized beside D-02's ROADMAP.md and STATE.md**
  because four planning operations have no `ok` arm without an `## Active`
  section naming the phase's ids. If the human would rather those four record
  only their refusal arms in phase 2, that is a CONTEXT change, not a
  deviation to take here.
- **Fixture provenance is checked locally only.** Rebuilding from the tag
  needs `v3.7.12` in the checkout, and the CI jobs clone at depth 1 without
  tags; plan 2's drift job checks recordings against the frozen JavaScript,
  which is the property that matters in CI.
- **`CADENCE_TEST_SEAM` stays closed (D-13).** `detect-commands`'s
  reachability is pinned by the scratch PATH (node and git only) rather than
  by `CADENCE_DETECT_REACHABLE`, so the recording is the unreachable arm with
  the tool named in `warnings[]`.
- **Local toolchain**: Node 26.8.1, git 2.55.0; CI runs Node 22 and 24 for the
  JavaScript suite and the recorder's own drift job pins the major the
  recordings name (plan 2 Task 4), so the recorder and builder use no API
