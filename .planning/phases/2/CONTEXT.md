## Durable decisions

- D-01 (direction, OQ-2): A `/cad-task` on a repository with no `.planning/` finishes. Its report states the risk check's verdict and says the receipt did not land because there is no planning root; git is the code record. The mandatory-record direction (refuse before the first commit, name adoption) was considered and rejected: every seam the task calls already answers `ok:true, written:false` and creates nothing, the check itself genuinely runs and returns a real verdict, and the prose rail-1 guard and atomic conventional commits still hold there. What a treeless run cannot deliver is a durable Cadence receipt, and the report says so. Evidence: measured live 2026-09-02 on a scratch repo with no `.planning/`; `cadence-core/bin/lib/trace.mjs:1110-1209`, `cadence-core/bin/planning/task-record.mjs:132-143`, `cadence-core/bin/planning/risk-check.mjs:386-450`, `cadence-core/bin/git-guard.mjs:190-192`, `cadence-core/workflows/task.md:60-69`; ROADMAP.md OQ-2.
- D-02 (rule): A `written:false` whose reason is an absent planning root reports done with the disposition stated. A `written:false` for any other cause - a symlinked trace, an unwritable `tasks/<slug>/`, a full disk, the size cap - still withholds done. The two are told apart on the envelope's own `reason`, never on a `[ -d .planning ]` check beside the seam. Evidence: `cadence-core/bin/planning/task-record.mjs:244-259` (`written` and `reason` always present), `cadence-core/workflows/task.md:50-52` (the seam's answer is the gate; a second way of asking drifts).
- D-03 (surfaces): When `risk-check run` refuses `surfaces-unanswered`, the coordinator asks the one-time surface question in the run and re-runs with `--surfaces`, so the blocking detection genuinely runs for the audience the inline arm exists for. On a treeless repo the answer is not persisted and is asked per run. Rejected: reporting the check as not run (`checked:false`, cause `surfaces-unanswered`) and completing, which leaves the blocking gate never running for a fresh user; and deferring to its own issue, which leaves the roadmap's "completes" criterion true only for users who answered globally. Evidence: measured live (bare call refuses, `--surfaces auth` passes); `cadence-core/bin/planning/risk-check.mjs:199-256`, `cadence-core/bin/lib/config-merge.mjs:187-216`.
