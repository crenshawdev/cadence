## Scope boundary

In: Archive every non-current-cycle open item as a BLOCK under an in-file `## Archive` section, carrying one dated reason for the whole move rather than a per-item verdict; triage the current-cycle (v2.5.0) items individually against the live tree, each getting one verdict backed by evidence; requalify historical `(phase N)` tags; and publish the kept-item-to-phase assignment list phases 2 and 3 will consume.

SCOPE CUT, 2026-08-08. The original scope - a tree-backed verdict for each of 213 items, citation normalization, and a before/after recall measurement - was planned twice and failed review both times, at 15 tasks the second time. The cost was days of executor time for a queue nobody has read in nine milestones. The premise that replaces it: an open item carried unread across nine milestones is presumptively dead, and proving that one item at a time buys less than it costs. Only the 38 items this cycle captured earn an individual reading. What the phase goal actually requires is that recall stops returning stale material, and a block move achieves that in one operation.

Out: Fixing any defect the triage confirms - a kept item is re-verified and assigned, never fixed here (phases 2 and 3 own the fixes; v2.5.0 phase 1 already closed some, and those are recorded as closed by v2.5.0 phase 1 rather than re-triaged). Changing `parseCaptureSnippets` or any recall behaviour. Changing the absent-vs-empty corpus contract. Retro-fitting verdicts onto the 51 already-checked items. Editing `skills/cad-capture/SKILL.md` or `cadence-core/workflows/execute.md` (see D-10). Tracking the capture queue (D-01).

Deferred: None - the size answer was "multiple plans, same phase", so nothing left this phase.

Plan shape: ONE plan, few tasks. After the scope cut the phase is a block move plus ~38 individual readings, which fits a single executor dispatch comfortably. Any plan that grows past roughly five tasks has reintroduced the scope this cut removed.

## Durable decisions

- D-01 (Queue durability): `.planning/CAPTURE.md` and its `## Archive` stay gitignored and untracked. The triage output is a working-tree artifact that does not survive a clone, and "name the commit that closed it" means citing the sha of the commit that closed the DEFECT, not committing the queue. Evidence: `.gitignore:23` ("Raw planning queue - local recall only, keeps candid working notes out of the public repo"); `git ls-files .planning` lists PROJECT/REQUIREMENTS/ROADMAP/STATE and the `_archive-*` dirs, no CAPTURE.md; the file was tracked only until `79c93ea` (2026-07-17), when it held 12 bullets.
- D-02 (Corpus policy): D-04 of the capture reader STANDS - closed items keep their place in the live queue and the corpus, carrying the generated `[closed] ` prefix. AMENDED 2026-08-08 by the scope cut: the archive now takes every non-current-cycle OPEN item as a block, not only the moot ones - but the rule this decision actually protects is unchanged and load-bearing, namely that `- [x]` CLOSED items stay in `## Todos` and stay in the corpus. Closed items are not archived under either scope. Reasoning: closed items are 51 of 270 corpus docs (18.9%), so removing them buys little, while `planning-files.mjs:602-609` argues they are exactly the prior evidence recall exists to surface - a `[closed]` item currently ranks FIRST on the query `git guard tokenizer` (score 9.9223). The corpus shrinks from deleting moot items, not from hiding fixes. Evidence: `cadence-core/bin/lib/planning-files.mjs:602-609`, `:622-628`.
- D-03 (Archive site): The archive is a `## Archive` section appended inside `.planning/CAPTURE.md`, not a sibling file. It is invisible to recall with zero code change because the section walk is hardcoded to `['Todos','Seeds','Notes']` and the reader takes one exact filename, and it inherits the existing ignore line. A sibling `.planning/CAPTURE-ARCHIVE.md` would be TRACKED by default, since `.gitignore:23` ignores only the exact path - publishing the candid notes on the next `git add .planning`. Evidence: `cadence-core/bin/lib/planning-files.mjs:614`, `:565-569`; `cadence-core/bin/planning.mjs:1341`; `.gitignore:23`.
- D-04 (Closure proof): A closure names either a commit sha or tree evidence - `verified live <date> against <repo-rooted file:line>`. The evidence form is admitted as a first-class third shape, not an exception. Reasoning: the file's own precedent already includes sha-less closures ("closed by task 7: verified 2026-07-30 that `config.mjs:226` compares through..."; "closed by RDM-01 (v1.4.0), verified live 2026-07-30"), and `PROJECT.md:116-119` states the guardrail as evidence from the tree "the same way a UAT item names its evidence", which a live verification satisfies. Requiring a sha strictly would push genuinely-dead items that no single commit closed back into the live queue permanently.
- D-05 (Tag namespace): Historical `(phase N)` tags are requalified to `(vX.Y.Z phase N)`; bare `(phase N)` is reserved for the current cycle. The requalified form deliberately stops parsing as a `phase` field, which is correct - those items are history, not this cycle's work. Reasoning: 179 of 213 open items carry an exact `(phase N)` tag but only 53 name any milestone in their text, so the tag cannot be resolved to a milestone from the item alone, and the numbers now span 1-6 - colliding exactly and completely with v2.5.0's own 1-6, and with this cycle's 1-4. Evidence: `cadence-core/bin/lib/planning-files.mjs:627` (`/^\(phase (\d+(?:\.\d+)?)\)\s*/` - anchored and strict, so `(phase 2, live friction)` yields no phase field); tag histogram at the re-pinned baseline `(phase 1)` x52, `(phase 2)` x49, `(phase 3)` x34, `(phase 4)` x20, `(phase 5)` x14, `(phase 6)` x10.
- D-06 (Citation form) - **SUPERSEDED 2026-08-08 by the scope cut; AC5 is dropped and no task normalizes citations.** Kept as the record of a real defect: the citation mixture below is still true and still worth fixing, so it survives as a capture item for a later cycle rather than as this phase's work. Original: Kept items' citations are repo-rooted from the repo root (`cadence-core/bin/lib/planning-files.mjs:429`), not basename-only. Reasoning: the queue currently mixes three rooting styles - of 142 `path:NNN` citations in open items, 87 are basename-only, 32 carry a slash but do not resolve from the repo root, and only 23 resolve as written - and the mixture already leaks into the test suite, which cites `CAPTURE.md:46` in one place and `.planning/CAPTURE.md:168` in another (`cadence-core/bin/config.test.mjs:479`, `:552`). One resolvable form is what makes AC5 checkable at all.
- D-07 (Measurement isolation) - **SUPERSEDED 2026-08-08 by the scope cut; AC4 is dropped and this phase records no before/after measurement.** The isolation argument below remains correct and should be reused verbatim by any later phase that does measure recall; what the cut rejects is spending this phase on the measurement, not the method. Original: Before and after recall runs execute with `--dir` pointed at a snapshot directory containing CAPTURE.md ALONE, so no phase artifact enters either side. Both raw JSON result sets, the query set, and the pinned `CADENCE_GLOBAL_CONFIG` go into `.planning/phases/1/MEASUREMENTS.md` - which IS tracked, so the "before" set survives even though the queue does not. Reasoning: measuring in place would conflate "moot items left" with "the phase's own artifacts arrived", and by the time this phase runs, v2.5.0 phases 1 and 2 will have added their own artifacts to `phases/` - which strengthens the isolation requirement rather than weakening it. The unit is recall's raw JSON line, not the `<recalled_memory>` block the workflows render, because that block is model-chosen (recall caps nothing - one query returned 78 results and 56,112 bytes). Evidence: `cadence-core/bin/planning.mjs:1353-1362`, `:1335-1338`; `cadence-core/bin/self-verify.mjs:94-95` (`--dir` is contract-legal on every subcommand); `cadence-core/bin/lib/config-merge.mjs:26`; precedent at `.planning/_archive-v2.3.0/3/MEASUREMENTS.md`.

## Decisions

- D-08 (Count drift): The open-item count is corrected to 213 in `.planning/REQUIREMENTS.md` and `.planning/PROJECT.md` (ROADMAP carries no figure). It has now drifted twice for the same reason - the queue grows while the docs quoting it do not: 182 -> 187 at gather time (2026-08-07), then 187 -> 213 at re-pin time (2026-08-08), the second move caused by v2.5.0 phases 1 and 2 capturing 26 new items and closing 12. The lesson is that any doc quoting a live count of an append-only file is stale on arrival; the count is therefore pinned to a stated date here rather than treated as durable. Evidence: `grep -c '^- \[ \]' .planning/CAPTURE.md` -> 213; `grep -c '^- \[x\]' .planning/CAPTURE.md` -> 51.
- D-09 (Roadmap claim corrected): The cycle-overview claim that "roughly a third of it describes code that no longer exists" is false and is corrected. Resolving all 62 distinct cited paths against the tree leaves only 2 unresolved (`.planning/phases/5/CONTEXT.md`, which survives only under `_archive-*`, and `PLAN-1.md`). The dominant triage cost is re-verifying line numbers and claims against files that all still exist, not chasing deletions.
- D-10 (Product divergence named, not fixed): `skills/cad-capture/SKILL.md:44-46` and `cadence-core/workflows/execute.md:294-296` both instruct committing `.planning/CAPTURE.md`. Under D-01 those steps are silent no-ops in this repo. The divergence is recorded here and left alone: fixing the ignore would publish the notes, and fixing the workflows is product behaviour this phase does not own. It belongs in phase 4's doc sweep if anywhere.
- D-12 (Consumer list narrowed by the renumber): The assignment list is consumed by phases 2 (live friction) and 3 (parser defects) only. Context reduction, which this CONTEXT was gathered expecting to feed, shipped as v2.5.0 phase 2 - BEFORE this triage - so it took its scope from `CTX-01`/`CTX-02` and its own context pass instead. An item the triage would have promoted to context-reduction work is assigned `unassigned` with a note, not back-filed into a phase that has already run. Reasoning: the reorder was externally prioritized (see ROADMAP overview) and the cost is stated there rather than hidden here.
- D-11 (Verdict scope) - AMENDED 2026-08-08 by the scope cut: individual verdicts are now required only for the CURRENT-CYCLE open items (the v2.5.0 set), not for all 213. Non-current-cycle open items take the one dated block reason at the head of `## Archive` instead, which is the whole point of the cut. Original scope: AC1 scopes to the 213 OPEN items present at the re-pinned baseline only. The 2 of 51 already-checked items that carry no verdict marker are noted but not retro-fitted - they are already out of the reading path, and widening to them turns a bounded pass into an unbounded one.

## Flagged assumptions

- The empty `- [x]` capture defect is live in code but has zero triggers in the current file - `if (!raw) continue;` (`cadence-core/bin/lib/planning-files.mjs:621`) runs before the checkbox strip at `:622-624`, so a text-less `- [x]` becomes a one-token `[closed] ` document that short-doc normalization floats to the top. Confident it is live; if wrong, phase 3 spends a task on a non-defect. The real risk here is that this phase's own edits CREATE the first trigger by cutting an item's text out from under its checkbox - the triage must not leave a bare `- [x]`
- Recall's cwd-relative `dir` defect is live at `cadence-core/bin/planning.mjs:1675`, not `:793` as the queue records - the behaviour is unchanged, the line moved. Confident; if wrong, any plan citing `:793` edits the wrong line. This is a kept item for a later phase, not phase 1 work
- The absent-vs-empty corpus conflation is asserted by a passing test (`cadence-core/bin/planning.test.mjs:3577-3588`) and documented as intended at `cadence-core/bin/planning.mjs:1299-1301`. Confident; if wrong, a triage verdict of "open defect" is really a contract-change proposal, and whoever picks it up breaks a green test and reads as having regressed something
- Only column-0 bullets enter the corpus (`cadence-core/bin/lib/planning-files.mjs:618`), so 5 items whose real argument lives in indented sub-bullets (`.planning/CAPTURE.md:96-99`) and 4 indented continuation lines (`:276,278,280,282`) are invisible to recall. Confident; if wrong, an item is closed or kept on a partial reading. Triage reads the FILE, never recall output
- Every open item is mechanically checkable with exactly ONE known exception - 212 of 213 carry at least one backticked code token, 167 name a file, 98 carry a `path:NNN` citation, and 1 has neither a backtick nor a filename (`.planning/CAPTURE.md:295`, a prose-only v2.5.0 phase-1 note recording that the published-version guard was deliberately loosened). Confident; if wrong, a plan that budgets a cheap "prose bucket" finds no such bucket and the phase is sized against a class that does not exist
- The close-out convention is inconsistent and must be NORMALIZED rather than merely followed: 6 `CLOSED` markers against 28 lowercase `closed by`, across at least six reference shapes, one of them a bare sha with no reason. The MOOT shape is uniform across its 4 uses and can be adopted as-is. Confident
