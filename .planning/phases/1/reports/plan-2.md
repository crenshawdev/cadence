Deviations: [deviation] Task 2 - expected the full planning suite to pass once the fallback was gated; observed one FAIL, `renumber remove: uncommitted work in phases/<at> is refused before any write`, at its final clean-remove assertion. Cause: the apply loop's `execFileSync('git', ['rm', '-r', '-q', <abs>], { stdio: 'pipe' })` passed no `cwd`, so git resolved the repository from the CALLER's process cwd rather than from `--dir` - confirmed directly, exit 128 with `'<path>' is outside repository at '<caller repo>'`. Every remove under a `--dir` outside the caller's repository had therefore been falling through to the `rmSync` fallback, tracked work and all, with `git rm` never running. The plan's Task 2 assumes that arm targets the phase directory's repository. Added `cwd: dir` to the call, the same targeting `uncommittedUnder` has always used, so the new gate fires on a real git failure rather than on a mis-targeted one.
