## Decisions

- D-08 (in-payload): `cmdFile` deduplicates its own payload, so a fire carrying one fingerprint twice spawns one create. No tracker lookup can catch that shape, and the 4-second gap between `#241` and `#242` is consistent with it as much as with a retry. Evidence: D-03's sites.
- D-09 (operator ceiling): The query is chunked at GitHub's DOCUMENTED five boolean operators, not the seven measured working here on 2026-09-03. A docs limit that the index enforces later is a silent truncation; extra round trips are not. Evidence: measurement at 3, 5, 6, 7 and 8 terms all `rc=0` with results growing monotonically, against GitHub's documented limit.
- D-10 (normalizer): A new normalizer is written BESIDE `normalizeDeclines` rather than widening it, and it carries the issue NUMBER as well as the fingerprint. `normalizeDeclines` returns `fingerprints: string[]` and drops `number`, and the file states its two readers "stay two on purpose". The number is what criterion 3's "reports the issue that already exists" needs, and no create face prints machine-readable output, so no create can supply one. The per-provider key differs (`number` / `iid` / `index`) exactly as `normalizeList` already handles. Evidence: `cadence-core/bin/lib/filing-decision.mjs:398-405`, `:427-446`, `:486-490`; `cadence-core/bin/lib/issue-decision.mjs:263,272,283`; precedent `cadence-core/bin/issue-check.mjs:330-333`.
- D-11 (refusal arms): "Incomplete" and "unavailable" are two arms, not one. A response that FILLED ITS PAGE refuses the fire before any create and names why; a lookup that COULD NOT RUN does not refuse and falls through to `FILED.md`. Collapsing them either makes an offline forge refuse every fire, contradicting criterion 4, or lets a truncated page read as "not filed". The removed code carried both reasons under those two names. Evidence: `cadence-core/bin/lib/filing-decision.mjs:407-412`; `readDeclines`'s local precedent at `cadence-core/bin/issue-filing.mjs:231-265`; `git show 5f4bcb97 -- cadence-core/bin/issue-filing.mjs`.
- D-12 (forges): All three arms ship with byte-exact pinned argv, the way the create vectors already are. GitHub is verified live here; tea 0.15.1 and glab 1.116.0 both carry a search face read from their own help text, and whether either matches a bracketed hex token in a title, or supports multi-term OR, is a flagged assumption. The header's measured CLI versions are re-measured in the same edit: it records gh 2.98.0 / glab 1.114.0 / tea 0.15.1 read 2026-08-25, against gh 2.99.0 / glab 1.116.0 / tea 0.15.1 installed today. Evidence: `cadence-core/bin/filing-decision.test.mjs:395-460`, `:470-483`; `cadence-core/bin/lib/filing-decision.mjs:460-472`.
- D-13 (invariant reconciliation): Reintroducing a lookup partially reverses the seam's "no forge CLI's stdout is read here at all any more" statement, and that reversal is written into the header rather than left as drift. `CONTEXT D-16` forbids CHILD BYTES on an envelope, not normalized values, so a fixed-phrase `detail` still holds. Evidence: `cadence-core/bin/issue-filing.mjs:9-14`, `:74-88`; `cadence-core/bin/lib/filing-decision.mjs:420-421`.
- D-14 (budget and census): `cadence-core/references/triage-gate.md` measures 25593 bytes against a `weight-budgets.json:51` ceiling of exactly 25593, so the prose edit raises that row in the same commit; its claims at `:302-303` ("spawns nothing, and has no page to fill") and `:335-341` ("Only the accepts cross the network") go stale and are rewritten. The `GH-244` requirement id is minted at `/cad-plan` by `seed-reqs`, never hand-added here. ## Acceptance criteria

- [ ] AC1: A `file` fire with at least one accepted finding issues exactly one tracker lookup before any create, title-scoped on the fire's fingerprints and chunked at five boolean operators. `filing-decision.test.mjs` pins the lookup argv byte-exact for tea, gh and glab, and the walk asserting no row names a binary covers the new row.
- [ ] AC2: Given a complete lookup response carrying a payload finding's fingerprint, no create child is spawned for that finding and the fire's report names the existing issue number. Holds for a response where that issue is closed as well as one where it is open.
- [ ] AC3: A lookup response that filled its page refuses the fire before any create and names the incomplete cause. A lookup that could not run does NOT refuse: it falls through to `.planning/FILED.md` and suppresses on a fingerprint with a row there.
- [ ] AC4: A create whose outcome could not be determined appends a `FILED.md` row marked unconfirmed, and re-running that same fire spawns no create and reports the issue that already exists.
- [ ] AC5: A fire payload carrying the same fingerprint twice spawns one create, not two.
- [ ] AC6: Running one fire twice leaves one `FILED.md` row per fingerprint. The append path skips a row whose fingerprint is already present, and `parseFiledRows` reads an unconfirmed row without minting a second recall entry.
- [ ] AC7: `node cadence-core/bin/test.mjs`, `npx tsc -p tsconfig.ci.json` and self-verify all pass, with `weight-budgets.json`'s `triage-gate.md` row matching its measured size and that file's stale claims at `:302-303` and `:335-341` rewritten.
