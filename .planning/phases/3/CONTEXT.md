## Durable decisions

- D-01 (Queue durability): `.planning/CAPTURE.md` and its `## Archive` stay gitignored and untracked. The triage output is a working-tree artifact that does not survive a clone, and "name the commit that closed it" means citing the sha of the commit that closed the DEFECT, not committing the queue. Evidence: `.gitignore:23` ("Raw planning queue - local recall only, keeps candid working notes out of the public repo"); `git ls-files .planning` lists PROJECT/REQUIREMENTS/ROADMAP/STATE and the `_archive-*` dirs, no CAPTURE.md; the file was tracked only until `79c93ea` (2026-07-17), when it held 12 bullets.
- D-02 (Corpus policy): D-04 of the capture reader STANDS - closed items keep their place in the live queue and the corpus, carrying the generated `[closed] ` prefix. Only MOOT items are archived. REC-02's "closed and moot items move out of the live queue" is corrected to moot only. Reasoning: closed items are 39 of 232 corpus docs (16.8%), so removing them buys little, while `planning-files.mjs:602-609` argues they are exactly the prior evidence recall exists to surface - a `[closed]` item currently ranks FIRST on the query `git guard tokenizer` (score 9.9223). The corpus shrinks from deleting moot items, not from hiding fixes. Evidence: `cadence-core/bin/lib/planning-files.mjs:602-609`, `:622-628`.
- D-03 (Archive site): The archive is a `## Archive` section appended inside `.planning/CAPTURE.md`, not a sibling file. It is invisible to recall with zero code change because the section walk is hardcoded to `['Todos','Seeds','Notes']` and the reader takes one exact filename, and it inherits the existing ignore line. A sibling `.planning/CAPTURE-ARCHIVE.md` would be TRACKED by default, since `.gitignore:23` ignores only the exact path - publishing the candid notes on the next `git add .planning`. Evidence: `cadence-core/bin/lib/planning-files.mjs:614`, `:565-569`; `cadence-core/bin/planning.mjs:1341`; `.gitignore:23`.
- D-04 (Closure proof): A closure names either a commit sha or tree evidence - `verified live <date> against <repo-rooted file:line>`. The evidence form is admitted as a first-class third shape, not an exception. Reasoning: the file's own precedent already includes sha-less closures ("closed by task 7: verified 2026-07-30 that `config.mjs:226` compares through..."; "closed by RDM-01 (v1.4.0), verified live 2026-07-30"), and `PROJECT.md:116-119` states the guardrail as evidence from the tree "the same way a UAT item names its evidence", which a live verification satisfies. Requiring a sha strictly would push genuinely-dead items that no single commit closed back into the live queue permanently.
- D-05 (Tag namespace): Historical `(phase N)` tags are requalified to `(vX.Y.Z phase N)`; bare `(phase N)` is reserved for the current cycle. The requalified form deliberately stops parsing as a `phase` field, which is correct - those items are history, not this cycle's work. Reasoning: 153 of 187 open items carry an exact `(phase N)` tag but only 53 name any milestone in their text, so the tag cannot be resolved to a milestone from the item alone, and the numbers collide head-on with v2.5.0's own 1-6. Evidence: `cadence-core/bin/lib/planning-files.mjs:627` (`/^\(phase (\d+(?:\.\d+)?)\)\s*/` - anchored and strict, so `(phase 2, live friction)` yields no phase field); tag histogram `(phase 2)` x56, `(phase 3)` x41, `(phase 1)` x35, `(phase 4)` x27.
- D-06 (Citation form): Kept items' citations are repo-rooted from the repo root (`cadence-core/bin/lib/planning-files.mjs:429`), not basename-only. Reasoning: the queue currently mixes three rooting styles - 83 basename-only, 39 partial, 9 repo-rooted - and the mixture already leaks into the test suite, which cites `CAPTURE.md:46` in one place and `.planning/CAPTURE.md:168` in another (`cadence-core/bin/config.test.mjs:479`, `:552`). One resolvable form is what makes AC5 checkable at all.
- D-07 (Measurement isolation): Before and after recall runs execute with `--dir` pointed at a snapshot directory containing CAPTURE.md ALONE, so no phase artifact enters either side. Both raw JSON result sets, the query set, and the pinned `CADENCE_GLOBAL_CONFIG` go into `.planning/phases/3/MEASUREMENTS.md` - which IS tracked, so the "before" set survives even though the queue does not. Reasoning: measuring in place would conflate "moot items left" with "the phase's own artifacts arrived", and by the time this phase runs, phases 1 and 2 will have added their own artifacts to `phases/` - which strengthens the isolation requirement rather than weakening it. (As gathered, `phases/` did not yet exist and this CONTEXT.md was the first non-capture document the corpus would hold; that is no longer true, and the `--dir` snapshot is what makes the before/after comparable either way.) The unit is recall's raw JSON line, not the `<recalled_memory>` block the workflows render, because that block is model-chosen (recall caps nothing - one query returned 78 results and 56,112 bytes). Evidence: `cadence-core/bin/planning.mjs:1353-1362`, `:1335-1338`; `cadence-core/bin/self-verify.mjs:94-95` (`--dir` is contract-legal on every subcommand); `cadence-core/bin/lib/config-merge.mjs:26`; precedent at `.planning/_archive-v2.3.0/3/MEASUREMENTS.md`.

## Decisions

- D-08 (Count drift): The open-item count is corrected from 182 to 187 in `.planning/REQUIREMENTS.md`, `.planning/PROJECT.md` and `.planning/ROADMAP.md`. CAPTURE.md's mtime (2026-08-06) is after the docs that carry the 182 figure (2026-08-05); the file grew after the count was taken. Evidence: `grep -c '^- \[ \]' .planning/CAPTURE.md` -> 187.
- D-09 (Roadmap claim corrected): The phase-1 overview claim that "roughly a third of it describes code that no longer exists" is false and is corrected. Resolving all 62 distinct cited paths against the tree leaves only 2 unresolved (`.planning/phases/5/CONTEXT.md`, which survives only under `_archive-*`, and `PLAN-1.md`). The dominant triage cost is re-verifying line numbers and claims against files that all still exist, not chasing deletions.
- D-10 (Product divergence named, not fixed): `skills/cad-capture/SKILL.md:44-46` and `cadence-core/workflows/execute.md:294-296` both instruct committing `.planning/CAPTURE.md`. Under D-01 those steps are silent no-ops in this repo. The divergence is recorded here and left alone: fixing the ignore would publish the notes, and fixing the workflows is product behaviour this phase does not own. It belongs in phase 6's doc sweep if anywhere.
- D-12 (Consumer list narrowed by the renumber): The assignment list is consumed by phases 4 (live friction) and 5 (parser defects) only. Context reduction, which this CONTEXT was gathered expecting to feed as old-phase 4, is now phase 2 and runs BEFORE the triage, so it takes its scope from `CTX-01`/`CTX-02` and its own context pass instead. An item the triage would have promoted to context-reduction work is assigned `unassigned` with a note, not back-filed into a phase that has already run. Reasoning: the reorder was externally prioritized (see ROADMAP overview) and the cost is stated there rather than hidden here.
- D-11 (Verdict scope): AC1 scopes to the 187 OPEN items only. The 8 of 39 already-checked items that carry no verdict marker are noted but not retro-fitted - they are already out of the reading path, and widening to them turns a bounded pass into an unbounded one.

- [ ] AC4: `.planning/phases/3/MEASUREMENTS.md` holds raw `planning.mjs recall --dir` JSON for a stated query set at both the pinned baseline and after the triage, with `CADENCE_GLOBAL_CONFIG` pinned and the snapshot dir holding CAPTURE.md alone.
