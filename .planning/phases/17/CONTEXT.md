## Durable decisions

- D-209. cad-task is a pair of binary operations, task-open and task-close, under the task executor contract compiled from the same source as the phase executor contract, with the phase lease disabled and the protected-branch and risk disposition policy kept (D-107, D-118 as written). A task has explicit identity, inline or planned. Without a planning root the run is ephemeral: facts stay in memory, matched risk uses per-run temporary material, done states the risk disposition and calls the record unrecorded, and nothing is created; an absent root is classified by the task boundary, never inferred from an unrelated ENOENT. Under a planning root the task record is a store record rendered to .planning/tasks/<slug>/RECORD.md (PLAN.md beside it for a planned task), guard-protected, written and acknowledged before done, and a write failure refuses done naming the write. No phase 0, no global ledger, no implicit filing or config persistence. The five existing .planning/tasks/ directories stay as authored history. The frozen workflows/task.md and planning/task-record.mjs are deleted by the plan that replaces them.
- D-210. Every refused native apply is recorded on the log as one boundary decision carrying the answer's code, rule and slot, through the existing boundary and Response::Refused path, so a refusal the caller was told about is one the owner can find (D-140, docs/rationale/architecture-v4.md:222-224). The invariant the phase 12, 13, 29 and 33 regressions hold is restated: a refusal changes no execution, evidence, plan or verification record, and the journal gains exactly one refusal decision. A recorded reason over the cap carries the [cut] marker and the cap. Recording stays best-effort against a store that cannot take it; the answer is already decided. GH-265 closes under T3.
- D-211. Shutdown is a contract, not process exit. On transport end (EOF on stdin) or SIGTERM the resident stops admitting new requests, drains every admitted write, joins the writer thread within a drain bound of 10 seconds, then exits; a write still open at the bound is left to journal recovery, which validates the whole intent on restart (docs/architecture/store.md:65-74) and is never adopted blind. Caller cancellation stays a distinct contract (store.md:28-30): admitted work continues when a caller cancels. The bound is a constant in code, not a config key.
- D-212. Acquisition is bounded the way config acquisition already is (config/floor.rs:16-18): a source file read by the read layer or the recall corpus is bounded at 16 MiB, a store file (state, the decisions journal) at 1 GiB, checked on metadata before the read so the crossing costs no allocation. Crossing a bound names the file, its size and the bound instead of the content: the read layer answers incomplete with the note, search and recall skip the file with the note, the store refuses to open naming the file. The resident never loads a file over its bound. The store bound is a guard against a hand-edited or corrupt file, not a memory fix; the memory fix is D-215. Bounds are constants in code, not config keys.
- D-213. Every git subprocess the resident spawns runs under a deadline, registered per caller: the guard's branch observation under the hook's 10 s host timeout, the rail diff, the recall history and the pause git calls at 60 s, matching the landing subprocess deadline (landing/effects.rs:11-49). Past the deadline the child is reaped and the caller sees a limit disposition naming the command and the bound; no operation waits without one. A census test keeps the registered list equal to the Command::new("git") sites in crates/.
- D-214. The self-verify guarantees that survive the shell are regenerated as one Rust test in the workspace suite, whose consumer is cargo test in CI; there is no self-verify CLI command. The test renders every compiled instruction surface through the binary's own renderers and checks that every config key, wire operation, skill name, repository path and hook event it names exists at HEAD, that every schema key has a reader, and that every rendered file is under a named byte ceiling. The 15 recognizers of shell commands, script paths, node -e programs, agent files, rungs and preload graphs retire with the mechanisms they recognized. self-verify.mjs, self-verify.test.mjs and the lib modules only they use are deleted by the plan that lands the test, after the planner confirms no other consumer remains; the requirement rows CWT-02, CWT-03, #44, #74, RNG-01, RNG-02, ENF-02, TRN-01, TRN-02, HNT-02, HOK-02 and CEN-01 are noted as carried by T7 or retired with their mechanism, one line each, in the plan's notes.

## Truths

- T1. When a task is done with no planning root under the task executor contract, the owner sees done with the risk disposition stated and the record called unrecorded, no .planning/ and no tasks/<slug>/ created, and a blocking risk still blocking.
- T2. When a task is done under a planning root, the owner sees the task's commits and files in the binary's task record, rendered to .planning/tasks/<slug>/RECORD.md, acknowledged before done, and done refused naming the write when the record cannot be written.
- T3. When any native apply is refused, the owner sees that refusal on the log as one boundary decision with its code, rule and slot, listed by the why query, with every other record unchanged.
- T4. When the transport ends while admitted writes are queued, the restarting owner sees every admitted write acknowledged in the journal within the drain bound, nothing admitted after the close, and a write still open at the bound left to journal recovery.
- T5. When a file the resident acquires exceeds its acquisition bound, the caller sees the crossing named (file, size, bound) instead of the content, and the resident never loads the whole file.
- T6. When a git subprocess exceeds its deadline, the caller sees a limit disposition naming the command and the bound, with the child reaped, and no git subprocess in crates/ left without a registered deadline.
- T7. When a compiled instruction names something that does not exist at HEAD (a config key, wire operation, skill, repository path, hook event), the maintainer sees cargo test fail naming the surface and the name, from one test that renders every surface through the binary's own renderers.
