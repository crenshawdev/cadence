# Phase 8: Close four UAT gaps - Plan 6

## Goal

Effective configuration and role routing serve the skills and their shared intake service. Close the four unresolved UAT items in the shipped phase: enforce config ownership, prevent unanswered initialization, and supply the missing batch-refusal and active-dispatch response evidence.

## Must be true when done

- AC16 / UAT 15: Write/Edit attempts against the bound repo or global native config destination receive a literal binary denial, including aliases; grouped config apply can still save an accepted answer.
- AC15 / UAT 14: An unanswered or declined suggestion creates no planning root, config, or durable store output; identical accepted intake and suggestion answers produce the same literal stored bytes.
- AC2 / UAT 1: Every required pre-admission batch refusal preserves the literal destination bytes, including failed reload and aliased destinations; an independent reopened session reads those same bytes.
- AC11 / UAT 10: The active-dispatch service response retains the admitted identity, model, agent, rung and exact prompt under different valid current config; a separate new-dispatch fixture selects the newer setting.

## Context

D-46, D-49, D-50, D-51 and D-56 in CONTEXT.md bind this closure. UAT.md's four recorded causes and verifier-findings.json's matching gaps are the task sources; SUMMARY.md and Plans 1–5 describe the already shipped spine. Apply all seven rules in docs/rationale/acceptance-criteria.md. The two real-host observations remain solely in MANUAL.md. This is gaps mode, with one task per unresolved item, not phase replanning.
