### Rulings recorded in conversation 2026-09-19

Tracker create at landing is phase 20. T7 stays. Carry in 4.0 is the store keeping its records; prune deletes none of them and the carry directories are not ported. Prune writes no ARCHIVE.md; the pruned-phase label comes from the release tag (D-139), an untagged close is "an unlabelled close". Committed undo marks the native execution record undone.

## Durable decisions

- D-194. Carry is a property of the store, not a file move. Risk observations, settlement receipts and deferred members live in the store's records and survive a prune untouched; .planning/risk-carry/ and .planning/deferred/ are not ported and nothing in 4.0 writes them. A milestone close refuses, naming the record, while a phase it prunes has a confirmed risk observation without a settlement receipt or an unruled deferred member; a landing refuses publish and merge while any deferred member is unruled.
- D-195. Prune writes no ARCHIVE.md. Recall and cad-why read pruned phases from git history; the prune commit has exactly one parent and removes the phase directories, ROADMAP rows and REQUIREMENTS rows in that one commit, so the recovery in why/corpus.rs never meets an ambiguous parent. The label of a pruned phase is the release tag reachable from the prune commit, else "an unlabelled close (<sha8>)", which retires the ARCHIVE-heading label source.
- D-196. Every external step of a landing (push, PR or MR create, merge, tag push) requires an authorization record naming the landing and the step, recorded through the binary before the step runs. git.auto_close is retired and grants nothing, including when an imported repository layer still carries it true. Checkout of base, pull, tag and reap run only after a merge confirmation record, in that order, and reap refuses a branch the base does not contain.
- D-197. A landing is a record with one receipt per step. A step whose remote effect exists without its receipt is reconciled by reading the remote (the remote ref, the forge's PR state), recorded done, and never repeated. No paid or mutating external action is retried blind.
- D-198. Undo is a binary-owned writer. The hashes come from the phase's native execution record, else the SUMMARY manifest, never from a guessed git log; they are reverted by exact hash in reverse order. Committed mode reverts, marks the execution record undone so the phase derives planned again, and repairs the cursor. --no-commit mode stages the reverts and resets nothing. A conflict stops the undo with the reverted set recorded and no forced continuation.

## Decisions

- D-199. Phase-local. Version drift is a read before any write: the confirmed version must not already be a tag, and the manifest's version is compared with the newest tag; a disagreement is reported in the answer and the bump waits for the owner's confirmation. Which manifest is versioned is GH-268's question (phase 19); phase 15 reads the one the release path names.
- D-200. Phase-local. Tracker create at landing, the fingerprint lookup and FILED.md mirroring are phase 20. Phase 15's landing reads the tracker for the report and writes nothing to it.

## Truths

- T1. When a milestone close names a phase whose records are unsettled (a confirmed risk observation without a settlement receipt, an unruled deferred member), the owner sees the prune refused with each unsettled record named by identity, and every document byte unchanged.
- T2. When a prune is interrupted at any of its write points and retried, the owner sees one end state: the phase directories gone, ROADMAP and REQUIREMENTS rewritten once, no ARCHIVE.md, and a single-parent prune commit cad-why recovers; an unreadable input is refused before the first delete.
- T3. When a landing reaches an external step (push, PR create, merge), the owner sees the step refused until an authorization record names that landing and that step, refused while any deferred member is unruled, and git.auto_close granting nothing.
- T4. When a landing is interrupted after a remote step succeeded and before its receipt was recorded, the owner sees the resumed landing read the remote state, record the step done, and repeat no push, create or merge.
- T5. When the owner confirms the merge, the owner sees checkout of base, pull, tag and reap run in that order, none of them before the confirmation, and reap refuse a branch the base does not contain.
- T6. When the owner undoes a phase, the owner sees the manifest's commits, from the execution record else the SUMMARY, reverted by exact hash in reverse order by the binary; in committed mode the phase derived planned again with the execution record marked undone; in --no-commit mode nothing reset; a conflict stopping it with the reverted set recorded.
- T7. When a milestone release names a version, the owner sees a collision with an existing tag, and a disagreement between the manifest's version and the newest tag, each reported before anything is bumped or tagged.

## Flagged assumptions

- A local bare git repository on disk stands in for the remote in every check; forge CLIs (gh, glab, tea) are faked by executables on PATH that record their invocations and answer fixed JSON.
- The native execution record exists for every phase executed through the binary (phases 12 and 33); a phase with no record and a SUMMARY manifest is the legacy case T6 covers second.
- The deferred member's unruled state is enumerate_deferred's InitialState::Unruled (review/deferred.rs); settlement is a receipt phase 21 defines, and until then a member is ruled only through the existing review adjudication path.
- The single-parent prune commit is made by the binary's own committer, not by the model, so the recovery in why/corpus.rs is a fixed contract rather than a hope.
- Confirmation of a merge is an owner record through cadence_apply, not a poll of the forge; the forge's state is read by T4's reconciliation, not asserted by prose.
- The frozen JavaScript for land, milestone-prune, risk-carry, deferred-carry, release-bump and git-publish is deleted from this branch by the plan that replaces each surface (rule of 2026-09-11); their tests go with them.
