# Phase 1: Benchmark quick wins - Context

Gathered: 2026-08-07
Feeds: /cad-plan 1

## Scope boundary

In: A static-analysis path into execution that works unconfigured (`lint_command`
plus tree detection, and the `LSP` grant); one joined `.planning/trace.jsonl`
carrying routing, provider, lifecycle and outcome events under a per-phase
correlation id, with a renderer and an on-demand display; every `mergeLayers`
callsite either surfacing `warnings[]` or documenting why not, enforced by a
check rather than by habit; file-lease enforcement at the executor's commit step;
the `phase_diff` and lockfile routing-data corrections; fault-injection tests for
every `review-provider.mjs` failure path; a published-version guard on
`git-branch.mjs decide` plus the `/cad-health` drift rule; and issues #14 and #19
as prose.

Out: The extensibility items considered and cut for this phase - a plugin `Stop`
hook and a plugin MCP server, both confirmed supported by the host, both rejected
because the evaluation's extensibility gap asks for a versioned SDK, arbitrary
tool registration and broad MCP lifecycle, which neither delivers. Mechanical
version-drift detection in `/cad-audit` and self-verify (phase 4, FRI-03). The
`maxTurns` rollout and the `risk_surface` re-arm cap (phase 4, FRI-02). Parser
defects (phase 5). Context reduction (phase 2). Queue triage (phase 3), except
the two items this phase closes with tree evidence. Four gaps the evaluation
named and this project is not building at all: a cross-runtime execution kernel,
a universal peer-messaging fabric, a per-worker OS sandbox, and external
deployment history.

Deferred: None - the size answer was "multiple plans, same phase", so nothing
left this phase.

Plan shape: multiple plans. Eight criteria across five requirements, spanning
three new seam subcommands (`detect-commands`, `trace`, `lease-check`), a new
self-verify walker over `.mjs` source, a test-only transport injection seam, and
six prose surfaces; /cad-plan breaks it down rather than one executor dispatch
carrying all eight.

## Durable decisions

- D-01 (Leases): Lease enforcement is a `planning.mjs lease-check --phase N --plan k` seam the executor runs against its staged files in `<commit_protocol>`, beside the existing risk-surface gate - NOT a `PreToolUse` hook on `Write`/`Edit`. A violation is a `blocked` checkpoint naming the undeclared path. Chosen over the hook despite the determinism ladder's "inviolable rails move to hooks", because the hook fires on every write in every project the plugin is installed in, and it cannot reliably resolve which plan is writing: the branch name `cadence/phase-<N>-plan-<k>` is the only signal and it is absent on the sequential path and on orchestrator writes (`SUMMARY.md`, `reports/plan-<k>.md`). A rail that fires wrong gets deleted, not tuned. The seam form also covers the sequential path, which criterion 5 does not require but gets free. Evidence: `hooks/hooks.json` (one `PreToolUse` matcher today); `design-notes/improvement-roadmap.md:17`; `cadence-core/workflows/execute.md:228-233`; `cadence-core/bin/planning.mjs:1182-1225` (`cmdPlanOverlap` already parses per-plan `files:` lists, which `declaredPhaseFiles` does not).
- D-02 (Template gates): `templates/config.json` loses its pre-written `review.triggers` block entirely, rather than having `phase_diff` changed from `off` to `advisory`. A written gate WINS over the level's and warns (`route.mjs:533-548`), so changing the value keeps the override and only makes it prettier: a scaffolded repo later switched to `stakes: critical` would still have `advisory` beating `critical`'s `adjudicated`, which is the exact thing criterion 7 exists to stop. Dropping the block lets the level decide and closes the CAPTURE item recording three gate-disagreement warnings on every scaffolded resolve. Evidence: `cadence-core/bin/route.mjs:533-548`; `cadence-core/templates/config.json`; `cadence-core/route-table.json`.
- D-03 (Published-version comparand): `git-branch.mjs decide` compares the `PROJECT.md ### Active` milestone against the target repo's git tags (`git tag --list` at `--dir`), not against any manifest. "Already published" means a tag exists, which is language-agnostic and true in a project that is not Cadence; the seam already shells out to git for the current branch. Reading a version from a manifest was rejected because the only manifest reader in the tree reads Cadence's OWN `.claude-plugin/plugin.json` (`planning.mjs:75-88`), which in any other project would compare a user's milestone against Cadence's version. `branch-decision.mjs` stays pure by taking the published version as an argument. Evidence: `cadence-core/bin/lib/branch-decision.mjs` header ("a RELEASE number read from prose no path keeps current is how the wrong version ships"); `.planning/CAPTURE.md:29`.
- D-04 (Detection is a seam): The unconfigured lint/typecheck path is `planning.mjs detect-commands` returning `{lint, typecheck}` from the project's own manifests, not executor judgment in contract prose. Prose was the obvious choice - it is how `workflow.test_command`'s fallback already works - and was rejected because criterion 1 asserts behaviour "in a repo that configured nothing", and nothing in CI can prove a judgment fired. A seam is testable on fixture trees and carries a `CONTRACTS` row. Evidence: `design-notes/improvement-roadmap.md:17`; `skills/cad-executor-contract/SKILL.md` `<process>` step 2; `cadence-core/bin/self-verify.mjs:69-93`.
- D-05 (Lockfile exclusion): The `concurrency` surface keeps its `lock` and `locks` patterns; `matchSurfaces` gains a basename exclusion for `*.lock` and `*-lock.json` applied before the token match. Removing the two patterns was the simpler data-only edit and was rejected because it trades a real detection away to close a false one: `src/lock.rs`, `internal/lock/manager.go` and `db/locks.sql` would stop flooring with no test naming the loss. Excluding by basename names the lockfile class at the point it is excluded. Evidence: `cadence-core/bin/lib/risk-surfaces.mjs:37-44` (`pathTokens` splits on every non-alphanumeric run); reproduced live - a plan declaring `package-lock.json` returned `concurrency` matched on pattern `lock`, solo floored to critical.
- D-06 (Correlation id): The per-phase correlation id is DERIVED from data already on disk - the phase number plus the phase's `PHASE_START` sha - and never minted-and-stored. Every producer (`route.mjs`, `review-provider.mjs`) is a fresh one-shot process with no shared state, so a minted id would differ between two concurrent producers in the same phase, and the trace would join nothing on exactly the parallel path it exists to explain. Evidence: `cadence-core/references/seams.md:99` ("`route.mjs` runs per role per spawn"); `cadence-core/workflows/execute.md:66` (`PHASE_START` already recorded per phase); `.planning/STATE.md` is a fixed 4-line cursor and cannot hold one.
- D-07 (Append, not atomic write): Trace appends use `appendFileSync` and the size bound is enforced at write time, NOT the repo's `atomicWrite`. `atomicWrite` is `writeFileSync(tmp)` + `renameSync` - a whole-file rewrite with no append mode - so a read-modify-write would lose concurrent events under batched dispatch, making the parallel run the least trustworthy part of the record. Evidence: `cadence-core/bin/lib/planning-files.mjs:1686-1690`; `cadence-core/workflows/execute.md:228-236` (a whole batch of executors dispatched in one message).
- D-08 (Trace scope on the parallel path): A worktree executor emits no trace events; the orchestrator records dispatch, return, checkpoint and escalation brackets for each worker. The trace file is gitignored, so anything a worktree writes cannot ride the merge back, and the executor's return is a frozen five-field digest. Bracketing still satisfies "every worker, retry and verification branch attributable to the task that caused it"; inner tool-level detail is explicitly not captured. The alternative - the executor writing trace lines into its committed `reports/plan-<k>.md` - was rejected as widening both the executor contract and the report format for detail no criterion asks for. Evidence: `cadence-core/references/seams.md:63-96`; `skills/cad-executor-contract/SKILL.md` `<worktree_mode>` and `<report>`; `cadence-core/workflows/execute.md:236-244`.
- D-09 (Warnings enforcement is mechanical): Criterion 4 is enforced by a NEW self-verify check walking `cadence-core/bin/**.mjs`, not by ten hand-written file-header sentences. This needs a new walker, since self-verify's `mdFiles` traverses only `.md` surfaces. The stated precedent is `lib/route-relay.mjs:14-19`: "Another prose instruction alone was rejected for exactly that reason; a check is what makes the instruction's ABSENCE visible." Without it, the eleventh callsite's author is under no mechanical obligation. Evidence: `cadence-core/bin/self-verify.mjs:187-237`; `cadence-core/bin/lib/route-relay.mjs:14-19`.
- D-10 (Standing decision overturned, dated): This phase reverses a written policy and says so in the same commit. Both `cadence-core/bin/review-provider.test.mjs:3-6` ("The wire paths themselves are pinned in references/provider-api.md and deliberately untested here - no network in the suite") and `design-notes/improvement-roadmap.md:5-6` state the wire paths are untested by design. QW-05 makes them tested. The header comment is corrected rather than left contradicting the suite beneath it, so the next reader does not find two stated policies with no reversal between them. Evidence: the two citations above.
- D-11 (Transport injection): Fault injection reaches the six modes through a test-only base-URL override following the repo's existing `CADENCE_*` env-var precedent, because every failure mode lives past `https.request` and the three adapter base URLs are hardcoded. Precedent: `CADENCE_ROUTE_TABLE` (`route.mjs:67`), `CADENCE_GLOBAL_CONFIG` (`config-merge.mjs:26`), `CADENCE_PLUGIN_MANIFEST` (`planning.mjs:75`). Extracting pure helpers and testing those was rejected: it proves what a helper returns, where criterion 9 says "what the caller sees". Evidence: `cadence-core/bin/review-provider.mjs:58`, `:271-296`, `:380`, `:420`, `:467`.

## Decisions

- D-12 (Key shape): `workflow.lint_command` is a single `string_or_null` defaulting to `null`, cloning `workflow.test_command`'s five-surface footprint verbatim. There is no companion `workflow.typecheck_command`, so the CONFIGURED arm covers only what the user names while the DETECTED arm (D-04) covers both. The reach row and `purpose` must say so rather than implying the key covers typecheck.
- D-13 (Lint failure disposition): A lint failure surviving three attempts is a `blocked` checkpoint, not the existing "record it as an open item and move on" arm, because criterion 1 requires that the executor not reach the commit step. This narrows `<deviation_rules>` for this one case; state it there rather than leaving the two readings in tension.
- D-14 (Tools lint): `LSP` is added to `KNOWN_TOOLS` in `self-verify.mjs:164-165` as well as to both rung files' `tools:` lines. The lint is one-directional - it flags referenced-but-undeclared only - so a token outside the fixed vocabulary is scanned by nothing and "self-verify's tool lint passes with it" would otherwise be vacuously true.
- D-15 (Trace producers): The trace is written through a `planning.mjs trace` subcommand family that prose and seams both call, rather than each producer writing the file itself. Two of the four families exist only in orchestrator prose - lifecycle in `workflows/execute.md`, outcomes in `references/review-triggers.md` and `workflows/verify.md` - and have no script to hang a direct write on.
- D-16 (Display): `/cad-progress --trace` mirrors `--stats` exactly: a read-only early branch that writes nothing and does not walk `reconcile`. `progress.md`'s guardrail is amended to name both flags and to state that the trace is written by the seams, not by progress.
- D-17 (Torn-config decision surface): On a torn `.planning/config.json`, `git-guard.mjs` forces `ask` for a `git commit` and carries the parse warning in `permissionDecisionReason`, regardless of whether the current branch is in the defaulted `protected_branches` list. Keying it to a protected-branch hit would fire only when the user is on `main`, never in the case where their custom list is the thing that was lost. A warning still never produces a `deny`: the fail-open contract at `git-guard.mjs:23-24` stands.
- D-18 (Drop-out visibility): Criterion 9's "named to the user" half is not new prose. `references/review-triggers.md:149-158` already mandates emitting a visible line naming the degradation, and that mandate is what failed twice (`.planning/CAPTURE.md:9` and the earlier closed occurrence). The new work is the mechanical half: `review-provider.mjs` writes the degradation as a provider trace event itself, so the panel's composition is recorded whether or not the orchestrator relays it, plus a test proving the seam's reason reaches the fire site.
- D-19 (Halt remedy ownership): The `blocked`-halt remedy is orchestrator-side reconciliation in `workflows/execute.md`; the executor contract is not touched. `<worktree_mode>` already forbids `git merge`, `rebase`, `fetch` and `stash` outright and names reconciliation the orchestrator's serialized decision.
- D-20 (Remedy fallback): After the remedy fails twice, that plan falls back to the sequential path in the main tree - not a bounded re-dispatch loop. Every failure arm in `choose_path` already resolves to sequential, and a retry loop here would reintroduce on the execute path the unbounded re-arm that FRI-02 files against review triggers for phase 4.
- D-21 (Lockfile proof shape): Proving criterion 6's lockfile clause needs one fixture plan PER lockfile plus a separate `src/lock.rs` plan, because `matchSurfaces` returns at most one match per surface - the first path that hits (`lib/risk-surfaces.mjs:77-93`). A single plan declaring all of them proves only the first.
- D-22 (Failure-mode mapping): The six modes map onto existing `fail()` reasons rather than new ones: timeout and connection error to `transport`, HTTP 4xx/5xx and unknown model id to `http` with the status, malformed or truncated body to `bad-json` or `no-output`. An empty findings set is `ok:true` with `findings: []` and is NOT a degradation - treating it as one would name a reviewer that legitimately found nothing as a drop-out.
- D-23 (Version comparison helper): The comparison reuses `compareVersions` from `lib/release-decision.mjs` rather than a second semver reader, and `decideBranch` stays pure by taking the published version as an argument so it keeps running under `node --test` with no live git. `release-decision.mjs` keeps one module-private `SEMVER_RE` explicitly so no second reader can drift from it.
- D-24 (Health rule tier): `/cad-health`'s version-drift rule is prose-only this phase - a new numbered check beside the existing six. Mechanical detection in `/cad-audit` and self-verify is deliberately phase 4 (FRI-03) and must not be pulled forward.
- D-25 (Checklist siting): Issue #19's bug-patterns checklist is a new file under `cadence-core/references/` that `debug.md` reads on demand by `${CLAUDE_PLUGIN_ROOT}` path, not inline prose. `debug.md` is at 6510 B against a 6510 budget - zero headroom - and inlining would put it on phase 2's cut list one phase after it ships.
- D-26 (Verifier ladder): Issue #14 modifies level 3 (`Wired`) of the verifier's existing four-level ladder in place, adding the traced-value evidence requirement. No fifth level. Level 4 already carries the evidence vocabulary that level 3 borrows.
- D-27 (Closure grammar): Criterion 12's two closures follow phase 3's already-locked grammar - D-04's evidence form (`verified live <date> against <repo-rooted file:line>`) and D-06's repo-rooted citations - so phase 3 records them as closed by phase 1 and does not re-triage them.
- D-28 (Callsite count corrected): The `mergeLayers` callsite count is ten across eight files, not nine: `review-provider.mjs` (`:209`, `:231`) and `land-cleanup.mjs` (`:72`, `:114`) each carry two. `REQUIREMENTS.md` QW-02 and `ROADMAP.md` criterion 4 were corrected in place at context time.

## Acceptance criteria

- [ ] AC1: In a fixture repo carrying a lint script but no Cadence config, `planning.mjs detect-commands` returns that command, and an executor given a task whose edit fails it produces a `blocked` checkpoint with no commit for that task
- [ ] AC2: Both `cad-executor` rung files list `LSP` in `tools:`, `self-verify` returns `ok:true` with `LSP` in `KNOWN_TOOLS`, and a `cad-executor` dispatch completes normally on this machine, which has no code-intelligence plugin installed
- [ ] AC3: A completed phase leaves `.planning/trace.jsonl` holding all four event families under one correlation id, every worker dispatch paired to its return or checkpoint; `planning.mjs trace` renders it, `/cad-progress --trace` prints it leaving `STATE.md` byte-identical, and with `.planning/` read-only `route.mjs resolve` returns its envelope byte-for-byte unchanged
- [ ] AC4: A check over `cadence-core/bin/**.mjs` reports zero `mergeLayers` callsites that neither surface `warnings[]` nor carry the documented header sentence, and a torn `.planning/config.json` makes `git commit` return `ask` naming the parse failure on a branch absent from the default protected list
- [ ] AC5: `planning.mjs lease-check` returns `ok:false` naming an undeclared staged path, and an executor that stages one produces a `blocked` checkpoint instead of a commit, on both the parallel and sequential paths
- [ ] AC6: A freshly scaffolded `config.json` has no `triggers` block; `route.mjs resolve` returns `phase_diff: "adjudicated"` at critical and `"advisory"` at shipped with no gate-disagreement warning; `package-lock.json` at solo resolves solo while `src/lock.rs` still floors critical
- [ ] AC7: `review-provider.mjs` has a passing test for each of the six failure modes against a local stub, and a fired trigger whose reviewer drops out writes a provider trace event naming the reason
- [ ] AC8: With `PROJECT.md ### Active` naming a version `git tag --list` already contains, `git-branch.mjs decide` returns `ask` with `branch: null`; `/cad-health` reports the drift naming both numbers; `cad-verifier-contract` level 3 requires a traced value; and `references/bug-patterns.md` exists and `debug.md` reads it before the first hypothesis

## Flagged assumptions

- `LSP` is the exact frontmatter tool name and an unrecognized `tools:` entry is ignored rather than erroring the dispatch - Confident, verified against current Claude Code documentation at context time; if wrong, AC2's grant half fails loudly at the first dispatch and the task collapses to a recorded decision
- The `LSP` grant is harmless with no code-intelligence plugin installed - Likely; the docs state the tool stays inactive rather than erroring, but this is an empirical claim about the running host and AC2 proves it by dispatch, not by CI. If wrong, both rung files revert and the phase loses one criterion clause
- `node:https` can be pointed at a local stub through an env-var base override without TLS complications - Unclear; the choice between an env override, a replaceable module-level transport reference, and a loopback TLS server with `NODE_EXTRA_CA_CERTS` turns on Node behaviour the tree does not record. D-11 picks the env override on precedent; if it does not work, the fallback is the transport reference, at the cost of a seam with no precedent here
- `PHASE_START` is recorded for every phase that produces trace events, including a phase that never enters `/cad-execute` - Likely; if wrong, D-06's derived correlation id has no anchor for context-only or plan-only activity and the id falls back to the phase number alone, which still joins within a phase but not across re-runs
- The three new subcommands fit the existing `COMMANDS` dispatch shape without restructuring `planning.mjs` - Likely, from its 1,681-line size and flat table at `:1651-1670`; if wrong, the phase gains an unplanned refactor task and the plan count grows
