WHY A NEW FILE, NOT A land-cleanup.mjs SUBCOMMAND: land-cleanup.mjs's header pins "it only advises: it NEVER runs checkout, pull, or branch -D" and close-decision.mjs's header says "It never runs live git and never does I/O." git-publish is the ONE seam that actually mutates (runs `git push`); folding a live push into an advisory file destroys the advisory/acting boundary that is the whole point of the locked decision. It gets its own file, its own CONTRACTS row, its own test file, and a git-* name that places it in the git-domain family a reviewer scans.

=== SUBCOMMAND / ARGV ===
`publish [--dir <path>] [--remote <name>]` — argv only, never a shell string, never a refspec, never a branch arg, never an env-prefix.
- --dir  = planning root / repo the push runs in (default process.cwd()); used only as `git -C <dir>` (git consumes the next token as a path, so --dir can never act as an option).
- --remote = a remote NAME (default 'origin'). Parsed by the flag() helper copied verbatim from git-branch.mjs/land-cleanup.mjs (argv.indexOf('--flag') -> argv[i+1]); any token that is not --dir/--remote is ignored by the dispatcher.
- NO --branch, NO refspec, NO URL/path, NO -c/env passthrough exist by construction.
cad-land invokes EXACTLY (GitHub arm only, step 4b, before `gh pr create`): node "${CLAUDE_PLUGIN_ROOT}/cadence-core/bin/git-publish.mjs" publish --dir <planning-root>. (--remote defaults to origin and need not be passed.)

=== PURE DECISION FN ===
Name: decidePublish, exported from cadence-core/bin/lib/publish-decision.mjs. PURE, TOTAL (never throws on missing/mistyped input), zero live git, zero I/O — the decideBranch/decideCleanup discipline.
Inputs (all pre-resolved by the seam's I/O layer): { autoClose:boolean, currentBranch:string, protectedBranches:string[], remote:string, configuredRemotes:string[] }.
Output: { action:'publish'|'refuse', argv:string[], branch:string|null, remote:string|null, reason:string }.
Constants (module-local): SAFE_BRANCH = /^[A-Za-z0-9][A-Za-z0-9._\/-]*$/ (forbids leading '-', ':', whitespace, and every shell metachar — so a branch can never be an option or a src:dst refspec); REMOTE_NAME = /^[A-Za-z0-9._-]+$/ (rejects '/', ':', '@' — no path/URL can stand in as the remote).
Gates, FIRST FAILING WINS, all refusals total (argv:[]):
  1. autoClose !== true                                  -> refuse, reason 'auto-close-off'
  2. !currentBranch || currentBranch === 'HEAD'          -> refuse, reason 'no-branch' (empty rev-parse / detached / not a repo)
  3. !SAFE_BRANCH.test(currentBranch)                    -> refuse, reason 'bad-branch' (leading-dash / metachar / colon)
  4. protectedBranches.includes(currentBranch)           -> refuse, reason 'protected-branch'
  5. !REMOTE_NAME.test(remote)                           -> refuse, reason 'bad-remote' (path/URL/colon/@)
  6. !configuredRemotes.includes(remote)                 -> refuse, reason 'remote-not-configured'
  7. else publish: argv = ['push','--set-upstream', remote, `refs/heads/${currentBranch}:refs/heads/${currentBranch}`], branch=currentBranch, remote=remote, reason 'sanctioned unattended integration-branch publish'.
Totality: coerce a non-array protectedBranches/configuredRemotes to []; a non-string branch/remote falls to a refuse; NEVER throw. The pure fn returns the FULLY-BUILT argv (minus the runtime `-C <root>` prefix) so a unit test asserts the vector byte-exact and that the branch string appears ONLY inside the one refs/heads refspec token — that is what makes the injection surface falsifiable.

=== EXACT PUSH MECHANISM (git-publish.mjs I/O seam) ===
Resolution in the seam (mirrors git-branch.mjs readCurrentBranch degrade-to-"" pattern):
  const dir = flag('--dir') || process.cwd();
  const remote = flag('--remote') || 'origin';
  currentBranch = execFileSync('git',['-C',dir,'rev-parse','--abbrev-ref','HEAD'],{encoding:'utf8',stdio:['ignore','pipe','ignore']}).trim()  // '' on throw
  configuredRemotes = execFileSync('git',['-C',dir,'remote'],{encoding:'utf8',stdio:['ignore','pipe','ignore']}).split('\n').map(s=>s.trim()).filter(Boolean)  // [] on throw
  autoClose via repoAutoClose(dir) — REPO LAYER ONLY: JSON.parse(readFileSync(join(dir,'.planning','config.json'),'utf8'))?.git?.auto_close === true, in try/catch, false on missing/bad/global-only (preserves git-guard's old review-finding-2 rule and D-08; a user-global auto_close must never enable unattended publish in an unrelated project).
  protectedBranches via mergeLayers(join(dir,'.planning','config.json')).config.git.protected_branches, default ['main','master'] (merged read — a broader global list only makes refusal MORE likely).
Then: const decision = decidePublish({ autoClose, currentBranch, protectedBranches, remote, configuredRemotes });
  if (decision.action !== 'publish') { emit({ ok:false, reason:decision.reason, branch:decision.branch, remote:decision.remote }); return; }
  try {
    execFileSync('git', ['-C', dir, ...decision.argv], { encoding:'utf8', stdio:['ignore','pipe','pipe'] });
    emit({ ok:true, action:'published', branch:decision.branch, remote:decision.remote });
  } catch (e) { emit({ ok:false, reason:'push-failed', detail:e && e.message ? e.message : String(e) }); }
Expanded live vector: `git -C <dir> push --set-upstream <remote> refs/heads/<branch>:refs/heads/<branch>`.
PROOF NO INJECTION SURFACE (all four killed bypass classes cannot be expressed): (a) program is the literal 'git' and args is a JS array — execFileSync execve()s git directly, NEVER /bin/sh, so ;/&&/|/backtick/$()/redirect-glue/trailing-& are inert bytes; (b) no string is ever concatenated into a command line; (c) no -c/--config/--config-env/global option is ever emitted (Class 2 dead); (d) the only variable tokens are dir (right after -C, a path, cannot be an option), remote (REMOTE_NAME-validated AND a live-configured-remote member), and branch (interpolated ONLY inside one refs/heads:refs/heads token, whose leading 'refs/' guarantees it is a ref not a flag); (e) no --branch/refspec/env-prefix is accepted, so Class 1 flag-decomposition and Class 3 env-prefix-in-a-string are structurally absent. The dest===src===current non-protected branch, so push.default=matching can never fan out to a protected ref (Class 4 dead).

=== SAFETY CHECKS (all in-code, none by parsing text) ===
- auto_close REQUIRED, REPO layer only (repoAutoClose) — D-08 preserved.
- protected-branch refusal (merged protected_branches, default [main,master]).
- detached/empty-HEAD refusal (branch '' or 'HEAD').
- current-branch-only: branch read from rev-parse HEAD; no --branch flag exists; refspec src===dst===branch.
- SAFE_BRANCH charset gate (defense-in-depth flag/refspec-injection guard, independent of git's own ref rules).
- bare-name remote via REMOTE_NAME AND live-`git remote` membership (a well-formed name that is not a real configured remote is refused; a path/URL can never be the destination).
- fully-qualified refspec eliminates tag/branch ambiguity, push.default surprises, and leading-dash-as-flag risk.
- fail-closed: rev-parse/`git remote` throwing degrade to ''/[] -> a refuse; a failing push emits ok:false reason 'push-failed' — the seam never silently proceeds.
- structured refusal halts the chain: any ok:false sets exitCode 1 (seam-io) and cad-land treats non-ok as "do not open the PR."

## Residual risks (documented, accepted)

- Env-prefix RCE is out of scope by the locked decision, not eliminated: the node seam inherits process.env, so a hostile agent could type `GIT_SSH_COMMAND=x node .../git-publish.mjs publish` from Bash. This cannot retarget the push branch or destination (both are validated non-caller values) and is identical to the pre-seam gh/glab path, which inherited env the same way; an agent that can set arbitrary env and run arbitrary binaries already has RCE by simpler routes. Both red-teams classify this as outside git-guard's threat model (accidental/unapproved pushes). Documented, accepted.
- A malicious origin URL is trusted: if an attacker already controls .git/config's remote.origin.url, the seam publishes the branch to that URL. This is game-over independent of the seam and matches the old exemption's own property (the remote NAME is validated; its URL lives in git config, never on our command line). Out of threat model.
- The seam hard-gates on a configured `origin` (or the passed --remote) existing in `git remote`: a repo with no origin gets a clean ok:false 'remote-not-configured' and cad-land halts. This is correct (gh pr create would fail anyway) but means the GitHub auto_close arm requires origin to be configured; intended, not a regression.
