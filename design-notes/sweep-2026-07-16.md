# Exhaustive code sweep — 2026-07-16

Four passes: my direct read of every `bin/` script + libs, and three parallel subagent sweeps
(workflows/skills drift, agents/references/templates contracts, tests/CI/packaging).
Everything below carries file:line evidence. Priority tiers: P0 = behavioral bug in shipped
code, P1 = prose/code drift and consistency, P2 = tests/CI/packaging, P3 = hardening/nitpick.

## P0 — Behavioral bugs

1. **git-guard: `git stash push` false-positives the publish rail.**
   `git-guard.mjs:47` — `/\bgit\b(?:\s+\S+)*?\s+push\b/` matches `git stash push`, so stashing
   inside a Cadence project fires the "workflows never push" ask. Same regex also matches
   quoted/argument tokens (`git log --grep push`). Fix: match the *subcommand* position
   (first non-flag word after `git`), exclude `stash`; add tests for both false positives.

2. **git-guard: subdirectory bypass.** `git-guard.mjs:46` — the guard only checks
   `cwd/.planning`. A `cd src && git commit` (or any Bash call with cwd below the project
   root) silently skips both rails. Fix: walk up from cwd to the git toplevel looking for
   `.planning/`.

3. **route.mjs: failure "escalation" can demote when ceiling < base.**
   `route.mjs:67-75` — `stepProfile` steps *toward* the ceiling in either direction. With
   `model.auto.ceiling: fast` (legal per schema) and base_profile `balanced`, a failed
   attempt re-dispatches at a *cheaper* profile — the retry gets a weaker model. Contradicts
   the function's own comment ("never dropping below base"). Fix: return `base` when
   `c <= b`; optionally cross-validate ceiling >= auto.base_profile at config-set time.

4. **model-hints: detected models steered into HTTP 400s.**
   - `model-hints.json:11` — bare `"mini"` rule tags every mini (incl. non-reasoning ones,
     e.g. gpt-4o-mini) `high_effort: true`; `review-provider.mjs:271` then sends
     `reasoning.effort` unconditionally → 400 at review time. Scope the rule to reasoning
     families or add older-family overrides above it.
   - `model-hints.json:18-19` — all `pro`/`flash` ids get `high_effort: true`, but the
     adapter sends `thinkingConfig.thinkingLevel` (`review-provider.mjs:306`), which
     provider-api.md:39-40 itself says Gemini 2.5 rejects (numeric `thinkingBudget`).
     Exclude 2.x from high_effort or branch the effort encoding.

5. **config.mjs: non-atomic write.** `config.mjs:151` — `set` writes with plain
   `writeFileSync`, unlike every `.planning` writer which uses `atomicWrite`
   (`planning-files.mjs:299-303`). A crash mid-write tears `.planning/config.json` (or the
   global file). Fix: use/extract the shared `atomicWrite`.

6. **Verifier → `uat merge` field mismatch (lossy, undocumented translation).**
   `agents/cad-verifier.md:164-173` emits Gaps as `truth/reason/artifacts/missing` and Human
   checks as `test/expected/why_human` (no severity), but the merge payload
   (`planning.mjs:330-372`) needs `name/reason/evidence/severity` and `name/expected`,
   matched by `name`/`k`. Rename the verifier's output fields to the merge schema (or
   document the mapping in verify-deep.md).

7. **execute.md: `PLAN PARTIAL` return has no route.** `agents/cad-executor.md:116`
   allows `PLAN {COMPLETE | PARTIAL}`, but `execute.md:89-95` handles only
   complete / checkpoint / timeout-or-no-report. Define PARTIAL handling (inspect log, ask
   user) or drop PARTIAL from the contract.

8. **Phantom flags in verify workflows.** `verify.md:47,86` (`--items -`) and
   `verify-deep.md:14` (`--findings -`) — flags planning.mjs never defines; payloads are
   stdin. Drop the flags, show the pipe.

9. **context.md: dirty tree after requirement-wording edit.** `context.md:262-264` stages
   "exactly CONTEXT.md and STATE.md" but the drift edit at :151-157 touches
   REQUIREMENTS.md — left uncommitted, violating conventions.md:57-58. Conditionally stage it.

## P3 — Hardening / idiom

37. **Seam-IO quadruplication.** `out`/`ok`/`fail` + exit-code mirroring re-implemented in
    all four bin scripts with *three different error idioms* (DONE-sentinel in
    config/review-provider; plain-return in planning/route; git-guard uses process.exit).
    Extract `lib/seam-io.mjs` — same move as planning-files/config-merge.
38. **git-guard stdout + process.exit.** review-provider.mjs:57-60 explicitly avoids
    `process.exit()` because it can truncate stdout on a pipe; git-guard.mjs calls `decide()`
    then `process.exit(0)`. Small payload, low risk — but it violates the codebase's own
    stated rule; use exitCode + natural drain.
39. **planning.mjs audit blind spot.** `planByReq` is first-wins (planning.mjs:414) — a
    requirement claimed by two plans is silently deduped; duplicate claims never reported.
    Emit a `duplicate_claims` field.
40. **uat merge silent drop.** A verifier gap matching a non-pending item is ignored with no
    trace (planning.mjs:350-358 else-path) — right invariant (never overwrite user results),
    wrong observability; return `ignored: [...]`.
41. **renderUat drops unknown fields** on round-trip (UAT_FIELDS whitelist,
    planning-files.mjs:149-150) — silent data loss for hand-added fields; preserve or warn.
42. **deepMerge `__proto__`** (config-merge.mjs:36) — plain assignment from parsed JSON keys;
    local-file threat model makes it a nitpick, but `Object.create(null)` or a key filter is
    one line.
43. **atomicWrite fixed `.tmp` sibling** — fine single-session; note if parallelization ever
    writes planning files concurrently.
